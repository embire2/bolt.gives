# bolt.gives v4.1.0

Stable web/server reliability release, 15 September 2026. This combines both
implementation phases and the isolated production-runtime migration. The private
native Windows client has an independent release line and is not replaced here.

## User-Visible Changes

- Keep current project source, conversation and runtime identity through follow-up
  prompts, navigation, reload and intentional Preview restarts.
- Stop false Ready/Repairing oscillation. Browser failures cannot be cleared by
  late HTML 200 responses; verified last-good restoration restores Preview.
- Remove the separate blocking FREE availability prompt. Actual generation uses
  the configured provider, and string/enveloped stream failures retain their
  retryable cause rather than becoming an unhelpful Unknown error.
- Give Calendar events persistent identities before follow-up-generated code
  reuses stored data, preventing missing React key warnings.
- Repair pricing, account-owned provider keys, onboarding scrolling/focus,
  Supabase connection status, browsing validation and recoverable installers.
- Run hosted projects in non-root containers with isolated, signed HTTPS Preview
  origins. Original production data and host configuration are retained.
- Enable the dedicated production Stripe webhook and real USD 5 monthly Checkout.
  Signed events, not browser redirects, control paid entitlements.

## Acceptance

1,462 tests pass with nine skipped. Strict module boundaries, typecheck, lint
(zero errors, ten existing warnings), production build and browser bundle budgets
pass. Six first-party templates pass actual Chromium Preview smoke tests.
Real-provider acceptance covers generation, follow-up, source/history restoration
and public Cloudflare publishing; injected hook/source failures are recorded
separately from ordinary generation. The service/routing rollback rehearsal and
frozen source/private-data checksum verification preceded the production cutover.

Production Stripe Checkout was inspected and expired without payment. The public
webhook rejects unsigned/tampered bodies and accepts signed replay; disposable
PostgreSQL checks cover activation, renewal, duplicates and stale events. A real
paid transaction remains the operator's test, not an automated charge.

See [browser recovery evidence](../quality/2026-09-15-browser-recovery.md),
[the roadmap](../../ROADMAP.md) and the historical checkpoint reports for the
distinction between demonstrated behavior and remaining validation.

## Install or Repair Linux

Use Ubuntu 22.04/24.04, a regular user with sudo access, Node.js 22 and sufficient
RAM for the build. Download the pinned installer and checksums from this release,
inspect the script, then run:

```bash
sha256sum -c SHA256SUMS.txt --ignore-missing
bash install-bolt-gives.sh --branch v4.1.0
```

For an existing installation, supply its current `--install-dir` and domains.
The installer preserves secrets, refuses divergent/rewritten source references,
uses bounded retries and retains previous builds when repair fails. PostgreSQL
is optional for platform profiles/admin data; generated projects do not require
a platform-provisioned database. Bring your own provider key and connect Supabase
or PostgreSQL only when your project needs data.

The PowerShell asset bootstraps the open-source server through WSL. PowerShell
5.1/7 and Ubuntu clean/repair CI pass; complete Windows/WSL reboot-resume is still
unverified. It is not a native Windows desktop installer.

## Remaining Work

The native Windows rewrite, full Windows/WSL lifecycle, wider BYOK/OTP/mobile/
collaboration matrices and fleet-scale profiling remain separate roadmap tasks.
The optional remote SSH CLI node is unavailable; core hosted Preview and
publishing do not depend on it. Rootless hosted updates use the operator-managed
deployment path; the legacy process-local updater stays disabled rather than
being given unrestricted sudo. No error-free or universal-provider claim is made.

expected/actual behavior and redacted diagnostics through
