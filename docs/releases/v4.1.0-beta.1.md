# v4.1.0-beta.1 - Combined Reliability Test Release

This opt-in prerelease combines the implemented work from both v4.1 reliability phases. **It is not stable v4.1.0, a production/fleet deployment, or a native Windows update.** Stable remains v4.0.1. Use a disposable private VM without customer data or production credentials; do not expose this beta as a multi-tenant service.

## Included Work

- Bounded, current runtime snapshots; durable history; read-only Preview refresh; saved follow-ups survive navigation, reload and deliberate runtime restart.
- Removed the blocking synthetic FREE startup probe and stopped scaffold/old health events from claiming a successful generated app.
- Fixed a newly reproduced FREE tool-envelope error: redundant artifact wrappers no longer become an empty file write, and nested commands/path changes are rejected before action emission.
- Pricing SSR and Checkout retry fixes, account-scoped provider keys, private database-free owner login and protected public web browsing.
- Exact browser environment allowlisting prevents `VITE_*` credential embedding. A bundled regression covers direct and whole-object access; credential-bearing public provider URLs are not exposed.
- Honest optional Supabase/PostgreSQL status, accessible login/onboarding, quieter event-driven commentary and safe source recovery.
- Recoverable Linux installation and Windows PowerShell WSL2 setup, including repeated release-tag repair, immutable-tag checks and prerelease-to-stable update ordering.

See the [full changelog](https://github.com/embire2/bolt.gives/blob/v4.1.0-beta.1/CHANGELOG.md) and [acceptance evidence](https://github.com/embire2/bolt.gives/blob/v4.1.0-beta.1/docs/quality/2026-09-12-phase2-checkpoint.md). Both passing and failed repeats are recorded; a healthy screenshot is not the whole release gate.

Local validation: **1,326 tests passed, nine skipped**; typecheck, lint (zero errors, ten existing warnings), boundaries and production build/bundle budget passed. The final real FREE/Luna browser journey reached an interactive Preview in about 28 seconds, applied a follow-up in about 12 seconds, and preserved the project through navigation, reload and runtime restart. It recorded no unexpected browser/HTTP errors; deliberate restart 503s were expected. A preceding repeat exposed the unresolved B15 crash below. Public source and rebuilt browser assets were scanned against 29 configured credential values with no matches. No production, Stripe payment or native Windows certification is implied.

## Test Installation

Download `install-bolt-gives.sh`, `install-bolt-gives.ps1`, `release-manifest.json` and `SHA256SUMS.txt` from the [release assets](https://github.com/embire2/bolt.gives/releases/tag/v4.1.0-beta.1). Verify their SHA-256 checksums before execution. Both installer assets default to this exact tag; the manifest records its source commit and prerelease restrictions. The GitHub source archives contain the same tagged public code; no private desktop source or credentials are included.

On Ubuntu 22.04/24.04, run as a regular user with sudo access in a disposable VM:

```bash
sha256sum --check SHA256SUMS.txt --ignore-missing
bash ./install-bolt-gives.sh --branch v4.1.0-beta.1 --skip-caddy
```

Keep the test private; use an SSH tunnel for localhost access rather than opening the app/runtime ports to the internet. Generated projects need no PostgreSQL server. Rerun the same command to repair this exact tagged version. Installer failure is reported, not hidden: divergent local commits, invalid prerequisites and missing permissions require an explicit correction. Configuration and previous builds are preserved where recovery is safe; the installer does not promise to solve arbitrary OS failures unattended.

On Windows, compare the hashes printed by `Get-FileHash` with `SHA256SUMS.txt`, then run PowerShell:

```powershell
Get-FileHash .\install-bolt-gives.ps1, .\install-bolt-gives.sh -Algorithm SHA256
.\install-bolt-gives.ps1 -Ref v4.1.0-beta.1 -CheckOnly
.\install-bolt-gives.ps1 -Ref v4.1.0-beta.1
```

This installs the **open-source Linux server through WSL2**, not the native desktop application. If WSL2/Ubuntu is missing, use `-InstallWsl` and follow the explicit reboot/first-user instructions. Do not bypass your organization's PowerShell execution policy. Full WSL reboot-resume and native Windows UI/signing/migration validation remain open.
