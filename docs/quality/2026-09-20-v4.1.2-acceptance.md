# v4.1.2 Acceptance: 20 September 2026

## Real Provider and Browser Evidence

The dedicated Cloudflare alpha (`alpha.bolt.gives`) uses its isolated alpha
backend, non-root project execution and per-project TLS Preview origins.
A normal Chromium profile registered through the UI, selected FREE / GLM 5.3
Flash, submitted a Calendar request, waited for generated source and Preview,
then requested a second visible label without replacing the first.

The successful run completed in **160.2 seconds**. Both real OpenRouter streams
completed with HTTP 200. The runtime snapshot and visible Preview contained both
requested labels. Reload restored six messages, twelve source files and the same
runtime identity. Publishing produced a public Cloudflare app; a separate browser
loaded it after the coding runtime stopped and remained stopped. There were zero
fatal browser/network errors. Expected navigation cancellations and iframe
capability warnings are retained in the private trace rather than hidden.

The [actual screenshot](../screenshots/agent-mode-glm-v4.1.2.png) shows the restored
project and remaining API credits. Test accounts contain only operator-owned
fixture content, not customer data. Detailed logs/session material stay private.

### Failure Found Before the Pass

The first GLM run failed the follow-up assertion. GLM's mandatory default
reasoning consumed the old 2,048-token completion budget without producing code.
A healthy starter alone did not count as success. The adapter now requests the
supported `low` reasoning effort and a bounded 8,192-token build budget. A real
coding diagnostic and the complete browser repeat above both emitted executable
file actions. This is a provider-budget correction, not a weakened E2E assertion.

## Regression and Build Evidence

Production repeats exposed registration sharing the backend IP rate-limit
bucket, repair polling returning 403 during a port handoff, and isolated stale
port redirects losing their embedding permission. Each has targeted regression
coverage. Browser initialization now configures only the main app frame, never
an opaque generated-app iframe. The native onboarding selector was also corrected.

Direct-origin streaming is validated over HTTP/2 with Caddy's application-only
`Alt-Svc: clear` policy. Diagnostic body clones, forced browser protocol flags and
operator-created diagnostic sessions are not final acceptance evidence. Final
journeys retain chat-cancellation and browser-exception failures.

- 1,518 tests passed, nine skipped, running the filesystem/runtime suite as the
  non-root runtime user. Root execution guards remain enabled.
- Strict module boundaries, typecheck, lint and production build/bundle budgets
  passed; lint retains ten existing warnings and no errors.
- Chat owns its network reader through a backpressured pipe, independently of
  the SDK's retained UI reader. Regression tests cover incremental delivery,
  reader release at EOF/failure, actual cancellation and unchanged HTTP errors.
  Responses are not cloned or buffered to hide cancellation. Assigned-port asset
  retries remain read-only, ownership-checked and bounded to about one minute.
- Six first-party template packs passed real Vite/Chromium Preview smokes.
- Linux installer clean/repair contracts passed locally and in GitHub CI.
- PR preview deployment no longer references the unavailable Cloudflare Pages
  action or builds twice. Wrangler's assigned deployment URL must pass a bounded
  HTTP smoke before the workflow posts its ready comment.
- Concurrent quota records, run deduplication, ledger migration, private file
  permissions, corruption failure and the 22:00 UTC reset have regressions.
- A real alpha browser with an operator-owned profile and explicitly injected
  usage reached zero of 20 credits, displayed the pause/upgrade modal, showed
  the 00:00 GMT+2 reset and allowed dismissal for a personal provider key. A
  forged larger client allowance was rejected with HTTP 429. This fixture did
  not spend twenty minutes of real provider credit.
- FREE startup exposes only GLM 5.3 Flash, persists its exact model ID, keeps
  MagnetAPI as a separate personal-key provider and remembers banner dismissal.
- Account identity, default one-instance policy, admin on/off policy, cross-user
  cookies, admin proxy CSRF and expired/password-invalidated sessions are tested.
- Compiled alpha `/admin` and its Cloudflare proxy returned 200. The request-env
  binding regression prevents the previously reproduced server-side 500.
- Public default-admin login is blocked. Registry reads preserve credentials;
  unreadable data cannot silently reset accounts to bootstrap defaults.
- Configured secret values are scanned against tracked source and browser
  artifacts. Funded model, SMTP and admin signing keys remain backend-only.

## Operational Scope and Limits

Source checksums, readiness, canonical Cloudflare commit hashes and assigned
hostnames are checked during rollout. The public release acceptance attachment
records final production/fleet results against the exact published commit;
alpha acceptance alone is not proof of production rollout.

Mailtrap port-587 STARTTLS authentication and operator-only test delivery passed;
no customer mailing campaign was sent. Existing passwords and customer project
data were not changed. Backups remain available for deployment rollback.

This release does not claim a real paid Stripe transaction, a new native Windows
build, completion of the Supabase rewrite, or every MagnetAPI BYOK combination.
The optional remote SSH CLI node remains unreachable and reports provisioning
failure explicitly; hosted Preview and publishing work independently. These
items remain in the roadmap and are not waived by the GLM test.
